## 解释与边界

- 仅忽略空白后匹配，Office 不做字符归一化；文本召回衡量是否丢失原文单元，不能惩罚所有多余文本或证明语义正确。
- Word 按原 XML 顶层正文/表格读取；不覆盖页眉、图片、脚注、文本框等。位置匹配按表序号、行列序号；双方先按 XML gridSpan/vMerge、HTML colspan/rowspan 展开合并单元格，再按网格位置比较。
- Excel 真实文件指标只覆盖字符串单元格，按值及重复次数匹配，不证明行列正确，也不包含数值、日期、公式。行列对应及 0/False/公式另用 fixtures/merged.xlsx 控制样例核验，见 functional-checks.json。
- Word 顺序匹配采用单调向前定位，是顺序召回诊断，不是通用阅读顺序准确率。
- PDF 样本特意选择已发现异常的文件，存在选择偏差；其中一个是依赖库表单测试文件。只做问题复核，不能外推整体 PDF 错误率。解析失败按端到端片段未获取计分。
- PDF 页图可见的表单值也计入检查，普通文本层提取遗漏这些值就是本需求下的覆盖不足；不据此断言库不支持专用表单 API。
- PDF 归一化分数仅表示额外清洗可能修复的部分，不是当前解析器已实现的能力。
- 不将这些不同口径指标加权拼成一个“总体准确率”。详情、漏项和标准答案在 accuracy/results.json、accuracy/pdf-gold.json，页图在 accuracy/pages/。

复跑：`.venv/bin/python accuracy_test.py`。所有解析沿用此前保存结果，本测试不修改业务解析器。

## 未匹配项复核修正

- Word 源 XML 的文本框包含 Choice/Fallback 两套兼容表示，初版评分把它们拼成一段，且违背了排除文本框的范围。现已剔除，正文分母从 9624 修正为 9623。
- 现有实现的 3 个真实未匹配项是嵌套表格中的设备编号；Unstructured 的 2 项是正文存储的页码 -1-、-2-。
- Unstructured 的 Excel 48 个未匹配单元格（22 种不同值）经复核，均为实际换行变成字面量反斜杠+n；仅统一此换行表示后 48 项全部匹配。故 99.01% 是严格文本表示匹配率，不能称为内容丢失率；该样本归一化后的值召回为 100%。复验脚本：newline_diagnosis.py。
