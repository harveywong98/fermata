# 解析内容的字符检查

本轮未运行 Dify，检查对象仍是现有解析器和 Unstructured。只检查原文件测试中成功/空结果；失败、超时以及残留的不完整输出不纳入。

现有解析器有 50 份可检查输出，7 份命中启发式规则；Unstructured 有 60 份，8 份命中。规则包括 U+FFFD、异常控制字符、私用区字符、`(cid:N)` 和连续中文插空格。命中不等于解析错误，数字不能当作错误率。

|文件|观察|判断|
|---|---|---|
|企业级Agent工程架构大纲.pdf|两种解析器都输出 1,956 个 U+0001，例如 `企业级\u0001Agent\u0001`|明确的文本清洗问题，不能直接当干净正文入库；可能与 PDF 文本层有关，未确定根因|
|createFormAndUpdatePageCJKUserFont.pdf|Unstructured 输出 8 个 `(cid:数字)`，例如 `文本框从(cid:39032)面重用`|存在无法映射成正常文字的内容；这是依赖库测试样例，不能代表业务文件发生率|
|API 资产报告（日常报告 DOCX）|两种解析器输出 39 个 `�`|检查原始 `word/document.xml` 也有 39 个；原文件已经包含替换符，不能归咎于本次解析|
|Docker、API 安全、安域、SecFox 等 PDF|出现私用区符号，如 ``、``、网页图标|常见于项目符号或图标字体，不能一律算正文乱码|
|SecFox 手册等 PDF|正文出现中文字符间隔空格|可能影响短语检索，需要结合版面核验；分词教学示例本来就有空格，是规则误报，不能全局删除|

检查没有覆盖所有漏字、错字、阅读顺序和跨页表格问题。两种引擎输出相同不代表它们都正确；需要原始渲染页面/人工标注作为依据。

可复跑：`.venv/bin/python inspect_text.py`。逐文件计数与片段：character-audit.json。本轮未修改解析器或批量清洗原文。
