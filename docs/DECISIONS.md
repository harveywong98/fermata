# 当前选型与依据

本文只记录当前采用什么、为什么，以及何时需要重新评估。系统调用关系见 [ARCHITECTURE.md](ARCHITECTURE.md)，后续工作见 [TASKS.md](../TASKS.md)。原始实验按需查阅，不要求先读完所有报告。

| 选择 | 依据与取舍 | 重新评估的条件 |
| --- | --- | --- |
| 一个应用、内部模块分工 | 当前只有一个主应用，直接调用知识模块能减少启动和配置成本；代价是共享依赖与资源 | 多个应用共用知识库，或解析需要独立扩容时再考虑拆服务 |
| Docling 统一解析，PDF 使用 Native | 统一文档结构便于维护；本地已有 Office 和 PDF 测试。当前没有 OCR，不适合扫描件 | 扫描件、复杂版面、公式等成为实际输入时补专项验证 |
| BGE-base 候选召回 | 在本项目合成测试里兼顾召回与 CPU 成本；不是客户真实分类准确率 | 补充真实客户问题、变更业务目录或硬件后重测 |
| 父子分块与来源引用 | 子块检索、父块提供上下文；能定位文档和片段 | 发现上下文截断、跨章节依据或预算问题后调整 |
| 上传后预览、人工确认入库 | 检查解析与分块后才发布，降低坏资料直接进入检索的机会 | 批量入库需求明确后再设计后台任务与质量检查 |

## 原始实验如何处理

调研资料作为历史学习记录保留，供需要时参考；其中的方案和计划不约束当前实现，也不自动进入开发清单。报告、脚本、实验结果、网页、截图及模型配置纳入 Git；模型权重按后缀排除，虚拟环境、第三方仓库、下载包和大体积原始语料保留本地。

历史报告中的结论以当时的测试范围为准。现有代码已经采用 Docling，报告里“建议采用／尚未迁移”的措辞是历史状态，不是当前 TODO。

复现历史实验前，按该实验的依赖文件重建环境，并核对输入路径。结果 JSON 和清单里的旧绝对路径保留为原始记录；模型、原始语料等本地依赖需另行准备。

解析实验的 baseline 依赖旧解析器；需要复现时，先从历史备份恢复相应实现，再设置 `BASELINE_PARSER_DIR` 指向包含 `document_parser.py` 的目录。不要拿当前实现替换历史 baseline 后仍沿用旧结论。
